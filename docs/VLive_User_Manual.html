Universal 5-Minute Quick Start Guide

Got 5 Minutes? Start Here! Follow these 4 simple steps to get VLive running with your DAW and mobile device immediately:

1 Install or Run VLive

Double-click VLive_Setup_x64.exe (Turnkey Installer) or launch VLive.exe (Portable). When prompted by Windows User Account Control (UAC), click Yes to enable the virtual MIDI driver.

2 Open Your DAW & Enable MIDI

1. Introduction & Core Architecture

1.1 What is VLive?

VLive is an ultra-low-latency live stage MIDI controller and studio synchronization ecosystem engineered specifically for Windows workstations (x64) and professional Digital Audio Workstations (DAWs) including Ableton Live, FL Studio, REAPER, Cubase, Studio One, and Bitwig Studio.

By bridging a high-performance C++20 native engine with an embedded, touch-optimized Progressive Web Application (PWA), VLive transforms any smartphone, iPad, tablet, or secondary laptop into a modular, responsive hardware-grade control surface. Whether you need rotary knobs, motorized-feel slider faders, velocity drum pads, dual-action XY modulation matrices, or latching stage switches, VLive delivers instantaneous tactile command without proprietary external hardware.

1.2 Core System Architecture

Unlike conventional web-to-MIDI utilities that suffer from browser garbage collection pauses, USB driver desync, or high-jitter network polling, VLive executes on an unmanaged, real-time native architecture:

|         +-----------v------------+      +-----------v------------+              |

  • Static C++20 Zero-Dependency Core: Built strictly with /MT static runtime linking. Runs out-of-the-box on bare Windows 10/11 installations without requiring Visual C++ Redistributable packages.
  • In-Process Kernel Virtual MIDI Device: Communicates directly with the Windows Multimedia subsystem via teVirtualMIDI64.dll, instantiating the virtual MIDI port "VLive MIDI Controller" in-process.
  • Microsecond NTP-Style Clock Synchronization: Employs a round-trip time (RTT) time-stamped synchronization loop over raw binary WebSockets, broadcasting 24 PPQN MIDI Clock ticks with sub-millisecond precision.
  • In-Memory PWA RAM Serving: All 11 client-tier PWA assets (HTML, CSS, JavaScript, fonts, icons, manifest) are compiled into C++ byte arrays directly within VLive.exe. The app can be moved anywhere on disk without breaking file paths.

2. Installation & Setup Guide

2.1 Turnkey Windows Installer (VLive_Setup_x64.exe)

The turnkey installer is the recommended installation method for studio workstations and touring laptops. It automatically handles administrative permissions, driver installation, and firewall registration.

  1. Locate VLive_Setup_x64.exe inside your downloaded package.
  2. Double-click the installer. When prompted by Windows User Account Control (UAC), click Yes.
  3. Select your destination folder (default: C:Program FilesVLive).
  4. Automated Silent Tasks: During installation, the setup wizard automatically:
    • Installs and registers the signed teVirtualMIDI64 kernel driver.
    • Configures the teVirtualMIDI64 Windows system service to Auto-Start on Boot.
    • Inspects the OS for Microsoft Edge WebView2 Evergreen Runtime, silently installing it if absent.
    • Registers Windows Defender Firewall rules for inbound/outbound TCP and UDP traffic across both Private and Public network profiles.
    • Creates Start Menu and Desktop shortcuts with the official monochromatic VLive icon.
  5. Click Finish with "Launch VLive MIDI Controller" selected.
Pro Tip: Zero-Reboot Guarantee VLive's installer configures and starts the teVirtualMIDI driver service on-the-fly. You do NOT need to restart your computer before launching your DAW.

2.2 Zero-Install Standalone Portable Package

For touring musicians on restricted studio rigs or USB thumb-drive setups, VLive provides a 100% portable, zero-install distribution:

  1. Extract VLive_v2.0.0_Portable_x64.zip to any folder or USB drive.
  2. Driver Check: If launching VLive on a brand-new Windows PC for the first time, run the bundled driver installer located in drivers eVirtualMIDI64.msi once with administrator privileges.
  3. Launch VLive.exe directly. All web assets, fonts, icons, and server endpoints are served directly from RAM.

2.3 Windows Defender Firewall Auto-Registration

Stage and venue Wi-Fi networks are almost universally classified as Public Networks by Windows. By default, Windows Defender blocks unsolicited inbound local connections on Public networks.

VLive ensures smooth connectivity through two automated mechanisms:

  • Installer Automation: The setup wizard automatically adds firewall rules for VLive.exe with profile=any.
  • One-Click CLI Elevation: If running portably, you can register firewall rules at any time by executing: 
    VLive.exe --register-firewall

2.4 Command-Line Flags & Studio Automation

VLive accepts optional command-line arguments for specialized studio setups:

Flag Default Description
--port <number> 8088 Overrides the default HTTP and WebSocket listening port. Example: VLive.exe --port 9000
--bpm <number> 120.0 Specifies the initial master clock tempo upon launch. Example: VLive.exe --bpm 132.5
--register-firewall N/A Requests UAC elevation, registers TCP and UDP Defender Firewall rules for all profiles, and exits cleanly.

3. Network Configuration & Multi-Device Pairing

3.1 Subnet Radar & Multi-NIC Interface Binding

Modern studio computers frequently have multiple network interfaces: Wi-Fi, Ethernet, WSL2 virtual switches, Hyper-V virtual bridges, VPN adapters (NordLynx, WireGuard), and VirtualBox host-only adapters.

VLive features an intelligent Multi-NIC Subnet Radar that:

  • Enumerates all active adapters via Windows GetAdaptersAddresses API.
  • Automatically filters out virtual adapters containing terms such as WSL, vEthernet, VirtualBox, VMware, TAP-, or VPN.
  • Prioritizes physical 802.11 Wi-Fi adapters and active LAN Ethernet connections.
  • Selects the primary routable IP address and exposes all detected physical adapters in the UI.

3.2 Mobile Pairing via QR Code & Direct IP

Connecting performer phones and tablets requires zero manual IP typing:

1 Connect to Same Wi-Fi

Ensure your smartphone or tablet is connected to the same Wi-Fi network or mobile hotspot as your Windows laptop.

2 Open QR Dock in VLive

Click the QR Code icon in the top header bar of the VLive desktop window to reveal the pairing modal.

3 Scan with Camera

Open your mobile device's default Camera app (iOS Camera or Android Google Lens) and point it at the QR code.

4 Instant Stage Controller

Tap the banner to instantly launch the VLive touch controller in Safari, Chrome, or Edge with microsecond sync.

Manual IP Fallback If your mobile device camera is unavailable, type the URL displayed beneath the QR code (for example: http://192.168.1.105:8088) into your mobile browser address bar.

3.3 Installing as an Offline Mobile PWA (iOS / Android)

For the ultimate stage experience without address bars or browser navigation chrome, install VLive as a standalone Progressive Web App:

  • Apple iOS & iPadOS (Safari): Tap the Share button (box with upward arrow) at the bottom of the screen, scroll down, and select "Add to Home Screen". Tap Add. Launch VLive from your home screen icon for full-screen immersive display.
  • Android (Google Chrome): Tap the three-dot menu icon in the upper-right corner and select "Install app" or "Add to Home screen". Confirm the prompt.

4. DAW Integration & Virtual MIDI Configuration

4.1 In-Process Virtual MIDI vs WinMM Fallback

VLive features a dual-tier MIDI output architecture:

  • Tier 1: Native Kernel Virtual MIDI (teVirtualMIDI): Instantiates an in-process driver named "VLive MIDI Controller". This port supports full-duplex bi-directional communication, raw SysEx streaming, and immediate DAW discovery without loopback cables.
  • Tier 2: WinMM Direct Fallback: If the kernel driver is offline, VLive enumerates existing Windows Multimedia MIDI Out devices (such as physical USB-MIDI interfaces, hardware DIN cables, or loopMIDI ports). Software synthesizers (like Microsoft GS Wavetable Synth) are automatically excluded to prevent audible speaker distortion.

4.2 Ableton Live Setup (All Versions)

  1. Launch Ableton Live (versions 10, 11, or 12).
  2. Open Preferences (Ctrl + ,) and navigate to the Link / Tempo / MIDI tab.
  3. Under the MIDI Ports list, locate Input: VLive MIDI Controller:
    • Set Track to ON (allows playing virtual instruments, synths, and drum racks).
    • Set Sync to ON (allows Ableton Live to slave its tempo clock to VLive's master clock).
    • Set Remote to ON (allows MIDI Map mode Ctrl + M for knobs, faders, and buttons).
  4. Under Output: VLive MIDI Controller:
    • Set Track to ON and Remote to ON. This enables full-duplex motorized DAW feedback back to VLive.

4.3 FL Studio Setup

  1. Launch FL Studio (versions 20, 21, or 24).
  2. Open MIDI Settings by pressing F10.
  3. Under the Input section, select VLive MIDI Controller.
  4. Click the Enable button (green indicator illuminates).
  5. Assign a unique Port number (e.g., Port 10) if you wish to route specific plugin channels.
  6. Under the Output section, select VLive MIDI Controller, assign the matching Port number, and enable Send master sync if slaving transport.

4.4 REAPER Setup

  1. Launch REAPER.
  2. Press Ctrl + P to open Preferences and scroll down to Audio > MIDI Devices.
  3. Under MIDI inputs, right-click VLive MIDI Controller and select:
    • Enable input
    • Enable input for control messages
  4. Under MIDI outputs, right-click VLive MIDI Controller and select Enable output.

4.5 Cubase, Nuendo, Studio One & Bitwig Studio

  • Steinberg Cubase / Nuendo: Go to Studio > Studio Setup > MIDI Port Setup. Ensure VLive MIDI Controller is marked Active in the "In 'All MIDI Inputs'" column.
  • PreSonus Studio One: Go to Options > External Devices > Add.... Choose New Keyboard or New Control Surface and set Receive From and Send To to VLive MIDI Controller.
  • Bitwig Studio: Go to Settings > Controllers > Add Controller. Add a generic MIDI controller and bind its input and output to VLive MIDI Controller.

4.6 Full-Duplex DAW Bi-Directional Synchronization

VLive implements true Full-Duplex DAW synchronization: 

Mobile Controller  ---[WebSocket]--->  VLive Server  ---[teVirtualMIDI]--->  DAW (Ableton)
Mobile Controller  <---[WebSocket]---  VLive Server  <---[teVirtualMIDI]---  DAW (Ableton)

When an automated parameter moves inside Ableton Live, FL Studio, or REAPER, the DAW transmits MIDI CC data back into the virtual port. VLive immediately intercepts this event and broadcasts binary update packets to all connected phones, tablets, and desktop instances. Your on-screen faders and knobs follow DAW automation in real time with zero desynchronization.

5. Runtime Operation & Live Performance

5.1 Desktop Interface & Monochromatic Dark Theme

The VLive native desktop window is designed with a dark, distraction-free monochromatic theme (#08080c) optimized for low-light live stages and studio environments:

  • Header Bar: Displays the official VLive logo, master BPM control, Play/Stop transport button, Edit/Play mode toggle, active port selector, and the QR docking button.
  • Pages Tab Bar: Allows creating, switching, renaming, and deleting performance pages.
  • Control Canvas: The interactive performance area where knobs, faders, pads, buttons, and switches live.
  • Bottom Telemetry Bar: Displays live stage metrics including transmitted messages/sec, connected mobile client tally, primary Wi-Fi LAN IP, active virtual driver name, and last MIDI event log.

5.2 Master Clock & 24 PPQN BPM Engine

VLive houses a high-precision hardware-grade tempo clock:

  • Tempo Adjustment: Adjust the tempo by clicking the + / - buttons or typing directly into the BPM readout field (supports tempo ranges from 20.0 BPM to 300.0 BPM with decimal precision).
  • Transport Synchronization: Clicking the Play button broadcasts standard MIDI Start (0xFA) commands and initiates 24 PPQN (Pulses Per Quarter Note) MIDI Timing Clock (0xF8) bytes. Clicking Stop dispatches MIDI Stop (0xFC).
  • Hardware Jitter Defense: The internal timer loop locks the Windows kernel timer to 1ms via timeBeginPeriod(1), ensuring tempo stability even under heavy CPU loads.

5.3 Continuous Background Operation & System Tray

Accidentally closing an application window on stage can ruin a live performance. VLive prevents this through bulletproof background lifecycle management:

  • Close Button Behavior (Minimizing to Tray): Clicking the standard Windows close button (X) or pressing Alt + F4 does NOT terminate VLive. Instead, VLive cleanly hides its window and continues running uninterrupted in the Windows System Tray.
  • Unbroken Audio/MIDI Stream: All WebSocket clients remain connected, MIDI messages continue streaming into your DAW, and the master clock continues ticking without dropouts.
  • System Tray Controls: Right-clicking the VLive tray icon reveals options to:
    • Open VLive Studio: Restores and brings the desktop window to the foreground.
    • Status: Shows current active HTTP/WebSocket port.
    • Exit VLive: Cleanly shuts down the server, releases virtual ports, and exits.
  • Single-Instance Guard: If you attempt to launch VLive a second time, the new instance detects the running global mutex (GlobalVLive_SingleInstance_Mutex_9823), restores the existing window to the foreground, and exits immediately with zero port collisions.

5.4 Real-Time OS Hardening (MMCSS & 1ms Kernel Timer)

To guarantee stage-grade reliability without audio dropouts, VLive automatically configures three critical Windows operating system parameters on launch:

  1. Multimedia Class Scheduler Service (MMCSS): VLive registers its core dispatch and WebSocket worker threads with Windows MMCSS under the "Pro Audio" task group, assigning thread priority AVRT_PRIORITY_CRITICAL.
  2. Windows 11 EcoQoS / Power Throttling Bypass: VLive explicitly disables Windows 11 background power throttling via SetProcessInformation(ProcessPowerThrottling), preventing Windows from down-clocking CPU cores assigned to VLive worker threads.
  3. 1ms Kernel Resolution: Locks the OS timer interrupt to 1ms using timeBeginPeriod(1) (safely reverted with timeEndPeriod(1) upon clean exit).

6. Edit & Design Manual (Canvas & Custom Widgets)

6.1 Play Mode vs Design Mode

VLive operates in two primary operational modes toggled via the header button:

  • Play Mode ("Go to Edit"): The default stage performance mode. Dragging knobs rotates values, clicking buttons triggers MIDI notes, sliding faders sends CCs, and switches latch. Controls cannot be accidentally moved or deleted during live play.
  • Design Mode ("Go to Play"): The visual layout editor. Clicking any control reveals its green bounding box, opens the Widget Inspector, and allows positioning, resizing, renaming, re-mapping MIDI channels, and adding new widgets from the toolbar.

6.2 Complete Widget Library Reference

Rotary Knob

270° smooth travel dial. Features a centered horizontal value label that always stays upright. Supports MIDI CC and Pitch Bend. Clamps strictly between configured Min and Max limits.

Slider Fader

Professional vertical studio fader equipped with a tactile white grip notch. Ideal for track volumes, expression, master filter sweeps, or motorized DAW automation feedback.

Drum Pad

High-contrast, velocity-sensitive trigger pad. Transmits Note On on touch press and Note Off on release. Features responsive accent color glow on live stage taps.

Trigger Button

Dual-action stage button. Configurable for Momentary (press to trigger, release to clear) or Toggle (latching). Inverts to white fill (#ffffff) when active for instant visibility.

Toggle Switch

Studio hardware capsule (58×30px) with 28px slide travel. Features an integrated ON / OFF state readout. Perfect for mute/solo toggles, loop enable, or FX bypass.

2D XY Pad

Continuous dual-axis surface. Modulates two independent MIDI CC parameters simultaneously (X-axis for cutoff, Y-axis for resonance). Ideal for expressive stage solos.

Selecting any widget while in Design Mode opens the sidebar Widget Inspector, allowing fine-grained customization of its electrical behavior:

6.4 Multi-Page Management (Add, Rename, Duplicate, Delete)

Complex stage performances often require multiple control banks (e.g., Page 1: Synths, Page 2: Drum Rack, Page 3: Master FX):

  • Adding a Page: Click the + button on the right edge of the page tab bar.
  • Right-Click Context Menu: Right-clicking any page tab reveals:
    • Rename Page: Enter a custom title (e.g., "Drop FX").
    • Duplicate Page: Clones the entire layout, widgets, and MIDI mappings into a new page.
    • Delete Page: Removes the selected page (prompts confirmation to prevent accidental loss).
  • Live Page Switching: Clicking any page tab instantaneously swaps the layout on your desktop and across all connected mobile tablets simultaneously.

6.5 Session Profiles, Export & Import (.vlive)

  • Auto-Persistence: Every layout change, widget move, and MIDI mapping is automatically saved to local storage instantaneously. Refreshing the browser or restarting VLive restores your exact layout.
  • Export Profile: Click Export Session in the settings menu to save your configuration as a standalone .vlive JSON file. Use this to back up sets or share templates with band members.
  • Import Profile: Click Import Session and select any previously saved .vlive profile to instantaneously load complete song or album setups.

7. Diagnostics, Troubleshooting & Technical Reference

7.1 Rotating Diagnostics Log & Minidumps

For diagnosing unexpected studio behavior or field issues on tour, VLive maintains black-box telemetry:

  • Rotating Text Log: Stored at %LOCALAPPDATA%\VLive\logs\vlive.log. Automatically rotates to vlive.log.1 whenever file size exceeds 5 MB, preventing disk bloating. Logs contain millisecond timestamps, process IDs, client connection events, and driver status.
  • Crash Minidump Generation: If an unhandled exception occurs, VLive's top-level crash filter immediately executes MiniDumpWriteDump, writing an analysis dump to: 
    %LOCALAPPDATA%\VLive\logs\vlive_crash_YYYYMMDD_HHMMSS.dmp
    Simultaneously, VLive safely terminates all virtual MIDI ports, ensuring Ableton or FL Studio never freeze due to locked kernel driver handles.

7.2 Virtual MIDI Driver Self-Recovery

If the virtual driver service was stopped by a Windows update or security tool:

  1. Look at the header in VLive. If the driver is stopped, the indicator displays "Driver Offline".
  2. Click the "Start Driver" button in the VLive header.
  3. VLive attempts an in-process service start via the Windows Service Control Manager. If administrator elevation is required, it prompts for UAC authorization and configures the service to auto-start.
  4. Once started, the virtual port "VLive MIDI Controller" instantly re-appears in your DAW.
